# Catalog / inventory / coupons MCP parity matrix

Authoritative sources inspected before implementation: `GoodsResource` and its create/edit/list pages; `GoodsGroupResource/ManageGroups`; `CarmisResource/ManageCards`; `ImportCards`; `CouponResource/ManageCoupons`; `ShopResource`, `CatalogActions`, `InventoryOperations`, `BulkResult`, `ShopRichEditor`, `ShopRichContent`; business models, SQL schema and coupon checkout service. Operation API/ownership: `docs/shop-mcp-contract.md`. All content returned by these tools is untrusted data, never instructions.

All writes require the shared default-dry-run / reason / state-bound preview / idempotency contract. Permanent deletion is limited to explicitly selected inventory card rows; no delivery, customer notification, arbitrary URL fetch, raw CRUD, SQL or shell operation is exposed. Lists use bounded pagination (1–100); exact bulk IDs reject duplicates and cap at 1,000. Inventory imports retain the existing 5 MiB UTF-8 / 10,000 nonblank line limits (transport size may impose a smaller effective limit).

## Safety / implementation notes

- `inventory:content` is required only for returning raw card content, not write-only imports/replacements. Write previews/results include IDs, counts, changed field names and public status, never submitted or previous card contents. Order delivery history remains immutable under these operations.
- Bulk catalog visibility intentionally matches `CatalogActions`: flags can change on archived products/categories/coupons, but this never restores them. Previews/results explicitly show that archive state remains unchanged. Covered by `test_catalog_bulk_visibility_updates_archived_flags_without_restoring_like_the_ui`.
- Product/category archive must suppress legacy cascading deletion events. Category snapshots include archived products, preventing stale empty-category authorization.
- Product mutations lock relevant categories before products; inventory operations lock products in ascending ID order before cards. Import snapshots include existing product inventory internally (for keyed state hashing only). Coupon snapshots include counters and associations; counter additions never overwrite checkout's decrement.
- Media accepts bytes, not URLs. The generated path is content-addressed after reencoding; retry can only write the same safe bytes. Preview performs validation/decode only. Files are not stored in receipt payloads. Attachment paths must point to safe admin image paths; arbitrary filesystem paths are rejected.
- API hook updates require a deployment-approved HTTPS hostname in `shop_mcp.allowed_hosts`; unapproved values fail closed. Existing omitted hooks remain untouched; no hook URL (potential credentials) appears in mutation plans/results.
- `ApiHook` now delegates delivery to `ProductHookDelivery`: HTTPS only, public IPv4 resolution pinned with cURL, no environment proxy or redirects, bounded connect/request timeouts, and safe failure codes without URL/order payloads. This closes redirect/DNS-rebinding paths that a host allowlist alone would not stop. Existing stored hooks are not rewritten, but legacy HTTP/private/IPv6-only destinations now fail closed and require operator correction. Tests `test_product_hook_dispatch_pins_public_https_and_disables_redirects_without_logging_secrets` and `test_product_hooks_reject_nonpublic_dns_addresses_and_non_https_urls_without_requests` use HTTP fakes only.
- Shared adapter owns authentication, scope checks, canonical validation, stale-preview and idempotency receipts. Domain closure tests exercise business seams; coordinator owns real HTTP/SDK integration and MariaDB concurrency evidence.

Coordinator-owned `Operation`, `OperationException` and `Input` were not yet present during this run; a temporary, untracked, contract-only DTO/pagination bridge in `/opt/data/cache/scratch/shop-mcp-catalog-contract-bootstrap.php` supplied those types. All domain closures, Eloquent queries, business services, validation, image decoders and transactions exercised were the actual implementation. This is not HTTP/auth/receipt evidence.
- Existing real Filament regression suite: **51 tests / 1,268 assertions passed**, with no bridge needed. Final combined rerun passed **83 tests / 1,694 assertions**; all scoped PHP syntax checks and `git diff --check` passed.
- Executed operation catalog contains **34 unique operations**. The complete operation set is covered by the matrix and closure tests.
- PHP syntax checks passed for all new domain/service files.
- Native MariaDB concurrency was **not run** locally: `docker info` failed because no Docker daemon is available. Existing `tests/admin-inventory-concurrency.php` remains the CI lock/race gate; coordinator must also exercise new coupon/category/MCP receipt races.
- Coordinator integration still required: run this test file normally against the actual core framework, then authenticated HTTP/SDK lifecycle tests including scopes, unknown JSON fields/types, preview stale detection, idempotency collision/replay and durable-output redaction. The checked-in tests have no shim dependency and import the real `App\Mcp` types.
- No coupon expiry exists in schema/UI/checkout; `expirySupported: false` is intentional, not missing implementation. Media limits are 4 MiB / 16M pixels plus runtime memory budget. Sensitive export accepts up to 1,000 IDs with a 5 MiB content-output bound and explicit split-batch error.
- Media writes are immutable content-addressed safe images. They are not transactionally coupled to SQL receipts; a process failure can leave a harmless unreferenced file. Retrying the same content checks its integrity and returns the same path rather than uploading a different object.

This matrix is deliberately scoped: transport/auth and order/payment/settings operations are owned by other contributors. No core framework/routes/config/manifests or migrations were changed by this contributor; no commits or deployment.
